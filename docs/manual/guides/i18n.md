# Localization

A game's text lives in catalogs -- one file a language -- and a script asks for
it by key, through `LocalizationService` (ADR 0154). The engine's own text is
kept the same way, and is read by the same call.

## The catalogs

`i18n/<locale>.json` at the project's root, beside `src/` and `content/`: one
flat object, keys dotted and area-first.

```json
{
  "$comment": "English.",
  "menu.play": "Play",
  "hud.score": "Score: {score}",
  "hud.lives": {
    "one": "{count} life left",
    "other": "{count} lives left"
  }
}
```

`i18n/en.json`, `i18n/pt-BR.json`: the file's name is its locale. Adding a
language is adding a file.

Placeholders are `{name}`. A value may also be an object keyed by plural
category, chosen by an argument named exactly `count`, by the rule of the
catalog's own language -- English has `one` and `other`; a language with more
adds its own. A missing category falls back to `other`.

## Asking for text

```luau
--!strict
local Localization = game:GetService("LocalizationService")

playButton.Text = Localization:Translate("menu.play")
score.Text = Localization:Translate("hud.score", { score = 42 })
lives.Text = Localization:Translate("hud.lives", { count = 3 })
```

A key is looked for in the player's locale, then in the project's default
locale, then in the engine's own text. **One that nobody has comes back as the
key itself**, with one warning in the log: a missing translation shows you which
key is missing, and never stops a game.

Arguments are strings, numbers and booleans.

## The player's language

`Localization.Locale` is the locale text is asked for in. It starts as:

1. what the player chose last time;
2. else the system's language;
3. else `[project] default_locale`;
4. else `en`

-- each narrowed to a catalog the project has. A Portuguese reader on a game
with `pt-BR.json` is shown it whether their system says `pt`, `pt-PT` or
`pt-BR`; one on a game with no Portuguese gets the default.

A language menu is a list and an assignment:

```luau
for _, locale in Localization:GetLocales() do
	addButton(locale, function()
		Localization.Locale = locale
	end)
end
```

**Writing `Locale` is the player choosing**: it is kept in their folder and is
where the game starts next time. A locale the game has no catalog for is
refused.

## Text does not change by itself

A label's `Text` is a plain string: it shows what it was given. When the
language changes, set it again:

```luau
local function refresh()
	playButton.Text = Localization:Translate("menu.play")
end

Localization.LocaleChanged:Connect(refresh)
refresh()
```

While a game is being made, a catalog saved in an editor is read again and
`LocaleChanged` fires -- so a screen written this way shows a corrected word
without a restart.

## The default locale

```toml
[project]
default_locale = "pt-BR"
```

The locale a key falls back to and the reference `ludwerk check` compares the
others against: **every key the default locale has must be in every other
catalog**, or the check fails and names each one. A key only another locale has
is mentioned and does not fail.

## In an export, and on a server

`ludwerk build` carries `i18n/` with the game.

A dedicated server has no player: `Translate` there reads the default locale,
whatever `Locale` says, and a write to `Locale` raises. In a multiplayer game
`LocalizationService` belongs to the player's side -- send a key and its
arguments, and translate where it is shown.

## The engine's own text

The engine's messages are keys too (R3): `i18n/en.json` in the engine, read
through the same call under the names they have.

```luau
print(Localization:Translate("scene.err.number_positive"))
```

A game's own key of the same name wins, which is how a game rewords a caption
of a screen the engine ships.

Errors that reach Luau carry their key in front:

```text
[scene.err.parent_cycle] Cannot parent an instance to its own descendant.
```

That is what lets a test match on the key rather than on prose.

Three catalogs ship and are translated separately:

| Catalog | Covers |
|---|---|
| `i18n/en.json` in the engine | The engine and its editor. |
| `tools/cli/i18n/en.json` | The command-line tool. |
| `i18n/<locale>.json` in a project | A game's own text. |

## What is not here

- **Instances are not translated for you**, and there are no translation
  tables in the tree: text is asked for and set.
- **The editor's language is another setting** than the game's.
- Plural rules beyond the catalog's, gendered text and list formatting.
