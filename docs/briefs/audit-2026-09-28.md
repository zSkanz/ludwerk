# Engine audit, 2026-09-28: failures, performance, security

Asked for by the owner on 2026-09-28: a full audit, **focused on errors, failures
and performance**, with security and quality after. Eight read-only reviews in
parallel (script runtime, networking and replication, content readers, renderer
and RHI, simulation core, application host, tooling, and a measured run of the
examples on the release package), then the most severe findings re-read in the
code before they were written here. Nothing in the repository was changed by the
audit.

How to read it: every item has an ID from the review that found it (S script, N
network, F files, R render, E simulation, A app host, T tooling, P measured
performance), a severity, where it is, what fails, and the fix. **Verified**
marks items re-read in the code for this report; the rest are the reviewers'
"confirmed by reading" unless marked *likely*. Each fix needs its own test that
fails first (the repository's rule), and each becomes a `docs/defects.md` row.

Security items are written as defects to close, not as attack recipes.

**N1 / S1 — a table key that is NaN, in a remote message, terminates the process.** Verified.
`engine/script/src/remote.cpp:236-248` (`Decoder::value`, `Tag::Table`) passes the
key to `lua_rawset` checking only for nil. Luau raises on a NaN key; Luau is built
with C++ exceptions (`LUA_USE_LONGJMP` 0) and nothing in `engine/app` or
`engine/script` catches `lua_exception`, so any peer's message ends the server.
The same unprotected decode runs in `startInvoke` and `deliverAnswer`.
Fix: reject NaN number keys and vector keys containing NaN in the decoder; run
every decode of foreign data under a protected call (`lua_cpcall`), which also
covers `LUA_ERRMEM`; and add a last-resort `catch` around the host's tick entry
points that logs and disconnects the offending peer instead of terminating.

**F1 — `.lmesh` animation channels are not validated.** Verified.
`engine/asset/src/mesh_format.cpp:985-1003` reads `channel.stride` with no check
that it is 3 or 4, matches the target, or that `values.size() >= times.size() *
stride`; `engine/render/src/animation.cpp:40-79` samples into `f32 sample[4]`.
A malformed pack or mod mesh corrupts the stack on first playback.
Fix: require stride == (Rotation ? 4 : 3) and the values count in `decodeMesh`;
clamp in the sampler too. Also **F15**: skin joint indices are never checked
against the joint count (`mesh_format.cpp:784-796`) — validate at decode.

**F5 — script-controlled paths leave the project.** Verified (`require`).
`world_host.cpp:90` `normalisePath` splits on `/` only, so a backslash path, a
drive letter or a UNC name passes as one segment. The same unvalidated join is in
`LoadScene`/`LoadSceneAsync` (`readContent`, `engine.cpp:1511-1516`,
`world_host.cpp:1373-1378`), `contentState` (`world_host.cpp:1275`) and stamp
names (`engine.cpp:1501`, `editor.cpp:1594`, `partition_cache.cpp:196`).
Effect: sandboxed Luau can read or probe any file, and on Windows a UNC path makes
an SMB connection that leaks the user's NTLM hash.
Fix: ONE function validates every script- or content-supplied relative path (no
root name, no backslash, no `..` escaping, no `:` in a segment, canonical result
under the root) and every caller uses it.

**F2, F3, F4 — content references reach outside the content root.**
- F2: glTF external buffer/image URIs are opened as given
  (`engine/asset/src/gltf.cpp:1364-1368` with fastgltf `LoadExternal*`): any file,
  or a UNC share, on thumbnail generation and import. A URI to a huge file makes
  fastgltf allocate it inside `noexcept` (terminate).
- F3: importing a glTF copies its companion files to `folder / relative`
  (`engine/app/src/content_tree.cpp:818-837`) with no containment check: files can
  be created outside the project.
- F4: texture, sky and URN resolution fall back to `root / raw string`
  (`render/src/mesh_loader.cpp:35-41,459-460`, `sky_loader.cpp:106-110`,
  `asset/src/content.cpp:92-121,265-266`); `asset://C:/...` or `//host/...` pass
  `isValidUrn`. Reachable from scene files, scripts and likely a replicated
  property.
Fix: the same single resolver as F5 for every content reference, no raw-path
fallback; a fastgltf map callback that refuses non-local URIs and caps reads at the
declared `byteLength`; containment check in the import copy.

**S4 — unbounded native recursion through synchronous resumes.**
`signals.cpp:515`, `:723` resume with `lua_resume(co, nullptr, ...)`, which resets
`nCcalls`; `task.spawn` resumes synchronously (`tasks.cpp:92`), so a function that
spawns itself (or a deep `require` chain, `modules.cpp:131`) overflows the native
stack and kills editor, player or server. Fix: pass `from = L` for synchronous
resumes, or keep a depth counter and raise past ~180.

**S5 — no watchdog for a script that never yields.** Verified.
Nothing sets `lua_callbacks(L)->interrupt` (grep); `architecture.md:707-710`
promises warn at 10 ms and a kill at 1 s in dev, and `script.warn.long_frame`
exists unused. `while true do end` freezes the game, the server, or the editor
with unsaved work. Fix: an interrupt callback checking a deadline armed at every
resumption.

**S8 — no cap on the script heap.** `runtime.cpp:226` uses `luaL_newstate()` with
the default allocator; `architecture.md:716-723` promises a cap from
`project.toml`, and the GC-step budgeting it specifies is not called. Fix: a
counting allocator that fails past the cap (Luau turns it into `LUA_ERRMEM`), and
the GC pacing the architecture describes.

**E1 / S9 — a live instance can be parented under a destroyed one.** Found by two
reviews independently. `engine/scene/src/world.cpp:370-374` only refuses a
retired parent; a destroyed-but-not-yet-retired one is accepted. After retirement
the child keeps stale parent and same-name links: `unindexName`/`unlinkChild`
return early, and the next same-name walk dereferences a retired id or loops
forever (`:924-926`, `:964`). Fix: refuse a destroyed parent (`parent_locked`);
clear sibling and same-name links even when the parent is gone; unparent live
children of retired parents in `retireDestroyed`.

**E2 — `Workspace:Raycast` over terrain never ends with an infinite or huge
direction.** `engine/asset/src/terrain_raycast.cpp:162`
(`for (along = marchStep; along <= maxDistance; ...)` with `maxDistance` = inf →
NaN step). A huge finite direction (a common "infinite ray" idiom) makes millions
of chunk lookups. Fix: reject non-finite directions, clamp reach, stop when the
ray leaves the field's bounds.

**E3 — NaN/inf from scripts reach physics.** `scene/src/native_accessors.cpp`
setters for `CFrame` (1153), `Position` (1174), `Orientation` (1190), `Size`
(1215), Weld `C0`/`C1` (1689-1715), Attachment `CFrame` (642);
`script/src/instance_binding.cpp:861` (`ApplyImpulse`), `:1142`
(`CharacterBody:Move`). The file's own rule (line 48) says physics scalars must be
finite; the 2D `ApplyImpulse` checks, the 3D ones do not. NaN also defeats
`sameShape`, so bodies are rebuilt every tick (`physics_sync.cpp:352`, `:458`).
Fix: finiteness checks in every setter and binding; a NaN-safe clamp in
`jolt_physics.cpp` `buildShape`.

**Network input from a peer (own review, defensive):**
- **Owned-state values unchecked.** `engine/replication/src/session.cpp:912-914`
  writes a network owner's `CFrame` and velocities straight into the authority's
  simulation; there is no `isfinite` anywhere in `engine/replication/src`. A
  non-finite value corrupts the authority's physics and replicates to everyone.
  Fix: reject non-finite values and clamp speed/position to sane bounds.
- **Intent action names interned forever.** `session.cpp:876`
  `world.atoms().intern(name)` for every name a peer sends, before the message is
  validated; the atom table never frees. Fix: `lookup`, and ignore names the
  authority has never seen. Intent axis values are also unchecked for
  finiteness — sanitise to 0 and clamp magnitude to 1.
- The networking review's full list was not delivered (only N1). **Re-review
  `engine/net/`, `engine/replication/src/session.cpp` and
  `engine/app/src/network_session.cpp` for missing bounds and per-peer limits**
  as part of this work, not only the two items above.

**T1 — the editor runs a `tools/cli/main.luau` found in the project's own
folders.** Verified. `engine/app/src/export_runner.cpp:66-78` (`locateCli`) walks
up from `projectRoot` and runs the first `tools/cli/main.luau` with Lute
(unsandboxed), as soon as the Export window opens. Affects repository/dev builds,
not the installed package. Fix: only the installed CLI, or the repository found
from `executableDir` / an explicit env var; never the project's ancestors.

**Crash reports found in the tree.** `examples/26-security-cameras/` holds two
untracked crash reports from 2026-09-27: access violation in
`D3D12_BindFragmentSamplers` via `renderer_default.cpp:4736`. Nine headless runs
did not reproduce it. Investigate (views + sampler binding) and delete the files.

## P1 — leaks, freezes, data loss

**Fixed so far** (2026-09-28): S2 with S3 (D233), S6 with the query half of
S11 (D234), S7 (D235), S10 (D236), A1 (D237), A2 (D238), A3 (D239), A4 (D240)
and A5 (D241). **Paused there on the owner's word**, for the multiplayer
smoothness brief (`multiplayer-smoothness-2026-09-28.md`). A6 is next when the
audit resumes. Its first reproduction on Windows showed that a file marked
read-only is still rewritten through `std::ofstream`, so the failure has to be
made another way (an injected writer), not by permissions.

**S2 — every `task.defer` leaks a registry reference.** Verified.
`signals.cpp:1063-1085` (`TaskCallback` in `drainDeferred`) never unrefs
`entry.threadRef`; same through `Scene:SendMessage` (`scenes.cpp:345`). Pins the
coroutine and everything it captures for the VM's life. Fix: unref after the
resume in every outcome.

**S3 — a resumed thread that parks again orphans its resumer's reference.**
Verified. `tasks.cpp:93-96` unrefs only `if (finished)`; the same pattern at
`tasks.cpp:283-288`, `services.cpp:2398-2401`, `:2505-2508`,
`net_module.cpp:282-285`, `save_service.cpp:528-531`, `remote.cpp:443-445`. Every
yield point takes its own fresh ref (`signals.cpp:647`), so
`while true do task.wait() end` leaks one slot per tick. Fix: unref
unconditionally after the resume.

**S6 — the atom pool for Luau names is exhausted by rebuilt strings.**
`runtime.cpp:39-54`, `binding.cpp:11-19`, `instance_binding.cpp:125-131`:
`internAtom` appends per string object, not per text; at 32767 it returns -1 and
valid member access starts raising `unknown_member`. Fix: map by text, fall back
to `atoms().lookup` on -1. **S11**: names, attribute/tag names, `ActionText`,
`ObjectText` intern into the append-only world atom table
(`native_accessors.cpp:154`, `:2090`, `:2106`, `instance_binding.cpp:512`) —
`bullet.Name = "Bullet"..n` grows memory forever. Use `lookup` on query paths and
keep free-form text as strings.

**S7 — a failed yield leaves its waiter registered.** `tasks.cpp:146-166` and the
same shape in `services.cpp:534-538`, `net_module.cpp:168-179`,
`signals.cpp:339-349`, `remote.cpp:383-387` register the waiter, then
`lua_yield` raises when not yieldable; the waiter later resumes the thread wherever
it is (double resume); `InvokeServer` has already sent. Fix: check
`lua_isyieldable` before registering.

**S10 — terrain brushes and timeouts are unbounded.** `instance_binding.cpp:1298-1320`
(brush radius/size never capped; `terrain:FillBall(v, 1e5, 1)` hangs then OOMs),
`asset/src/terrain.cpp:317-320` (float→int casts of huge values are UB),
`net_module.cpp:160` (`static_cast<u32>(timeout * 1000.0)`). Fix: cap voxels per
call, clamp before every cast.

**A1 — the close grace loop cannot finish a yielding handler.**
`world_host.cpp:1636-1667` loops `tick()` with no pacing and no event, network or
I/O pump; with `RunService` paused `tick()` returns at once
(`world_host.cpp:1026`), so a `BindToClose` waiting on `SaveAsync` is never
resumed: 30 s of "Not Responding", then the handler is abandoned. Also hits the
editor's Stop / save-all / open-scene paths. Fix: pace to the tick, pump events,
network and I/O, resume save waiters while closing even when paused.

**A2 — one failed terrain/voxel cell freezes the simulation forever.**
`field_streamer.cpp:383` with `asset/src/streaming.cpp:381-393`: `Failed` is
terminal and never `Resident`, and `waitingForGround` zeroes `simTicks` each frame.
Fix: a failed cell counts as settled (log an error) or is retried with backoff.

**A3 — the join timeout counts frames and ignores redial.** Verified.
`network_session.cpp:320` `++m_waited > m_joinTimeout` (600 updates): 10 s at
60 Hz, ~4 s at 144 Hz, milliseconds with a minimized window (A13); a `--join`
client whose server is not up yet silently becomes solo. Fix: wall-clock timeout;
no timeout while `m_redial`.

**A4 — a scene changed at run time does not stream, and the boot scene's cells
keep streaming.** Only the boot scene is partitioned (`world_host.cpp:542`,
`engine.cpp:1486`); `clearScene` keeps streamed instances
(`scene_file.cpp:2343`); `StreamingHost::setWorld` returns early
(`streaming_host.cpp:147`). Returning to the boot scene duplicates parts. Fix:
reset streaming and field indices on a scene change and partition the new scene.

**A5, A6, A12 and editor data loss.**
- A5: save-all after Play (`engine.cpp:2595-2617`) discards code typed in script
  tabs during Play (the Stop and device-lost paths write it back; this one does
  not).
- A6: `content_tree.cpp:514` rewrites references with a truncating `ofstream`
  after the rename, no rollback, errors counted as "no references".
- A12: `field_streamer.cpp:116`, `:155` overwrite a cell whose read failed with
  only the loaded part, and delete emptied cells before `index.json` is written.
- Also (medium): untitled scene discarded at quit when a stamp is open
  (`debug_overlay.cpp:10457`); device-lost "Save and restart" ignores save
  failures (`engine.cpp:5201-5220`); content-file tabs not retargeted on rename
  (`editor.cpp:1560`); material URNs not retargeted; document saves use a
  non-durable write.
Fix each with the durable write (`writeFileDurable`), compute-before-rename, and
rollback on failure.

**A7 — closing a dedicated server's console loses its saves.**
`platform/src/stop_signal.cpp:46-49` returns from `CTRL_CLOSE_EVENT` /
`CTRL_SHUTDOWN_EVENT` at once; Windows then terminates the process before
`BindToClose` and `flushSaves`. Fix: block the handler until `host->close()` is
done, within Windows' ~5 s. *Likely.*

**A8 — a `LoadScene` that fails leaves the game half torn down.**
`services.cpp:1255-1283` queues without checking; `world_host.cpp:1365-1379` only
logs `scene_not_found`; a malformed file is torn down (1406-1410) before the parse
fails (1415). Old instances stay, scripts are gone, `SceneLoaded` never fires.
Fix: resolve and parse before any teardown; fire a failure event.

**A10 — a scene change and a `Join` can interleave.** A scene still in its close
grace, or a prepared `LoadSceneAsync`, activates after a `Join` and runs
`loadScene` on a replica, mounting `server/` scripts there. Fix: `Join` cancels
pending scene changes; `applyPendingScene` refuses on a replica. *Likely.*

**A11 — a hot reload loses up to 1 s of save changes.** `reload.cpp:50`, `:85`:
the old host never flushes and `SaveStore::~SaveStore` joins without writing
dirty slots. Fix: `flushSaves()` before booting the fresh host.

**F7 — recovering a save from `.bak` then destroys the backup.**
`save_store.cpp:337-345`, `484-487`: the next write renames the damaged main over
the only good `.bak`. Fix: after a backup load, move the damaged main to
`.corrupt` and write the new main before rotating.

**F6 — stamp fan-out is bounded in depth only.** `scene_file.cpp:1932,2096-2116`
(`kMaxStampDepth = 4`): K children of a self-referencing stamp build ~K³
instances; every placement re-reads and re-parses the stamp file. Fix: a total
instance budget per load, and cache parsed stamps per load.

**F8 — image decode is unbounded and stb is built with every format.**
`asset/src/image.cpp:13-16,67-83`: no `STBI_MAX_DIMENSIONS`, no `STBI_ONLY_*`,
and the decoded buffer is copied (2× peak). Fix: cap dimensions, restrict formats,
check `stbi_info_from_memory` first, decode in place.

**F9 — floats are validated before narrowing, or not at all.** `scene_file.cpp`
2254-2256, 1766-1773; `terrain_cell.cpp:447,602`: block size, voxel size and
heights can become 0, denormal or inf → UB casts and 10⁹-step loops. Fix:
`isfinite` after narrowing; clamp voxel/block size to [0.01, 64], heights ±1e6.

**Crash diagnostics (A15).** The terminate handler is per thread on MSVC and is
installed on the main thread only (`crash.cpp:374`); `abort`/`__fastfail` never
reach the filter; logs and dumps go to `current_path()` (`main.cpp:802`); the log
is opened `wb`, so the previous run's log is lost. Fix: install on every engine
thread, add SIGABRT/invalid-parameter handlers, write to the user dir, rotate the
log.

## P1 — performance

**R1 — mesh LOD always picks level 0.** Verified.
`render/src/mesh_cache.cpp:378-380` reads the translation from `m[0][3]`,
`m[1][3]`, `m[2][3]`; `Mat4` is column-major `m[c][r]` (`core/math.h:100`), so
those are 0, the distance is 0, and every imported mesh draws full detail at every
distance in every pass. `axisLength` (`:393-397`) reads rows instead of columns.
The test fixture (`render/tests/mesh_cache_tests.cpp:286`) puts the offset in the
same wrong element. Fix: `m[3][0..2]`, column lengths, correct the fixture, and a
test that a distant instance picks a coarser level.

**R4 — material de-duplication in extraction is O(n²).**
`render_world.cpp:1451` (parts) and `:967` (MeshParts, no last-hit shortcut):
10k parts with distinct colours ≈ 50M compares per frame. Fix: a hashed index that
keeps insertion order (R10).

**E4 — `writeBack` is O(active²) per tick.** Verified.
`scene/src/physics_sync.cpp:1464-1476`: `std::any_of(m_active...)` inside the
active-body loop (5k active ≈ 25M compares per tick). Fix: stamp records with the
tick, or sort and binary-search.

**E5** weld/attachment resolution quadratic per tick (`physics_sync.cpp:1257`,
`:1237`, `:1112`, `:1042`); **E8** the navmesh re-gathers every tick and
`setProperty` bumps mutations before its no-change check (`world.cpp:700`;
`recast_navigation.cpp:487`, `:981-985`); **E9** terrain/voxel collider wanted-set
rebuilt and sorted every tick (`physics_sync.cpp:722-768`); **E10** change-queue
fan-out unfiltered by listeners, O(N²) on deep destroys (`world.cpp:388-413`,
`:131`); **E14** fluid wakes scanned in full each tick.

**R3 — views rebuild the terrain layer arrays every time they draw.**
`renderer_default.cpp:3927-4048`: `ViewportFrame`/`SubWorld` snapshots have no
terrains, so `updateTerrainArrays` releases the main world's arrays (~17 MB,
blits, mips) and the main view recreates them — every frame for a spinning preview.
Fix: key arrays per view, or release only after N frames unseen.

**R2 — with anti-aliasing off, tonemap writes to the swapchain through an Rgba8
pipeline** (`renderer_default.cpp:1373`, `:5366-5370`; swapchain is B8G8R8A8).
Undefined behaviour / debug-layer fatal. Fix: a swapchain-format twin, as
`fxaaViewPipeline_` does; check the outline composite (`:1417`) too.

**R5** `TerrainLoader::draws` O(N² log N) per frame (`terrain_loader.cpp:563-575`);
**R6** a `std::vector` per bind call in `sdlgpu_device.cpp` (1007, 1079, 1116,
1292, 1352) and vertex/index rebinds on every draw; **R7** a 4 KB joint palette
pushed per skinned draw per pass (`renderer_default.cpp:2924-2928`); **R9**
block-atlas tiles never reclaimed — after 256 textures ever seen, new blocks draw
untextured (`renderer_default.cpp:4302-4346`); **R10** a resizing `ViewportFrame`
recreates ~20 targets per size change and RHI slot tables never reuse
(`view_host.cpp:130,188`, `sdlgpu_device.cpp:42-52`); **R11** whole-buffer
rewrites never cycle (`sdlgpu_device.cpp:1165,1206,1284`); **R12** a surface
shader whose pipeline fails shows magenta one frame then silently draws built-in,
and a `waitIdle` per recompile; **R13** instance uploads above 4 MB bypass the
staging buffer; **R14** `create` leaks shaders on a missing-skinned-shader error;
**R15** per-frame allocations in extraction, foliage cull, clusters, UI text laid
out every frame. **S12** `SaveService:Set` deep-copies and re-serialises the whole
slot on every call; **S13** a new coroutine per handler per fire and O(N)
disconnects.

**Measured (P, release package, headless, 3 runs each, shared machine):**
- P1 **14-voxels: ~8% of frames take 8–17 ms (worst 37 ms) against a 0.29 ms
  median**, caused by block edits (mining ~90 slow frames per 1,800, water ~45).
  The engine has no per-phase timing, so remesh vs collider rebuild could not be
  told apart. Add per-phase frame stats, then fix the edit path.
- P2 **Headless memory grows ~1 GiB/s while the GPU falls behind** (11-ocean to
  4.1 GiB in 5 s; 28-arcade 196 MiB to 4.6 GiB across identical runs) and stays
  flat at 160×90: CPU work queued ahead of the GPU with no fence wait (R8,
  `engine.cpp:1787`, `:5139`; `two_worlds.cpp:473` already fixed this locally).
  Fix: keep 2–3 fences and wait on the oldest when not presenting.
- The flagship is healthy: 1.39 ms median / 6.5 ms p99 at 1080p D3D12 (M8 was
  5.35 / 8.79), 30,000-frame soak with instances flat and ~+10 MiB working set
  over 40 s (watch, not yet a leak). Under `--rhi=null` the worst frame doubled
  (10.3 vs 5.19 ms) on a loaded machine — re-measure quietly.
- **The package lags `main`:** `FoliageLayer` is missing from it, so the
  flagship's script stops at `init.luau:224` and foliage could not be measured.
  Rebuild the package before the next measurement.
- Every run of 04-obby and 10-open-world logs `The sound  is not in any mounted
  content directory` (empty name).
- Frame stats report no p95, no CPU/GPU split and no per-phase breakdown — add
  them; without them a regression cannot be attributed.

## P2 — determinism, robustness, tooling

- **E6** `m_characters` is an `unordered_map` iterated for `Landed` changes and
  retirement (`physics_sync.h:473`, `physics_sync.cpp:1483`, `:1305`): handler and
  slot order differ between MSVC and libstdc++ (ADR 0083). Use a sorted container.
- **E7** rollback does not save `movingUntilTick` / motion type
  (`physics_sync.cpp:1706-1800`): a re-simulation diverges. *Likely.*
- **E12** streaming destroys in hash order and budgets materialisation by
  `steady_clock` (`streaming_glue.cpp:218`, `:20`, `:31`).
- **S14** `math.random` is seeded from time by `luaopen_math` and never reseeded
  (`sandbox.cpp:115-142`).
- **E11** re-enabling a weld or moving an attachment skips the weld-cycle check;
  **E13** a job that runs inline on slot exhaustion ignores its dependencies
  (`jobs.cpp:492`); **E15** a stale `inWorld` memo for one tick.
- **A9 — the "Frame took 5391574 ms" left from D209.** A headless run that starts
  solo uses the synthetic clock; when `Join`/`Host` makes the network active,
  `FrameClock` switches to `steady_clock` since boot and the difference is the
  machine's uptime. Fix: `FrameScheduler::rebase(nowNs)` when the clock source
  changes. **A13** a minimized window runs uncapped (no swapchain wait) and pins a
  core; **A14** the catch-up warning is flushed on every clamped frame.
- **F10** a shipped game's whole content pack is read into memory at mount
  (`asset/src/pack.cpp:318-326`); the editor object store never evicts
  (`content.cpp:217-234`). **F11** terrain-cell decode amplification unbounded;
  **F12** chunk keys near `INT_MAX` overflow; **F13** JSON key lookup is linear
  and used inside loops (quadratic on large saves; save reads are not size-capped);
  **F14** `project.toml` numbers cast before clamping; **S15** save slot names
  accept `CON`/`NUL`/`AUX`/`COM1` and case-only duplicates collide on Windows and
  macOS.
- **Tooling:**
  - T2 `ludwerk android install-tools` downloads with no checksum and trusts
    cached archives forever (`tools/cli/commands/android.luau:52-65`);
  - T3 `[project] version` is not sanitised and escapes `dist/` in archive/APK
    names (`build.luau:449-451,534-536`, `export/desktop.luau:481-484`);
  - T4 the dev server relays observer messages to the engine without
    authentication and broadcasts the engine's token (`tools/cli/devserver.luau`,
    `dev_control.cpp:186-190`); the token comes from `math.random`;
  - T5 remembered keystore passwords are keyed only by path, so any project can
    sign with a remembered key (`export/android.luau:341-343`, `:126-133`);
  - T6 passwords stored in plain JSON with default permissions;
  - T7 control characters in `name`/`version`/`company` inject lines into the
    Linux `.desktop` file;

## Findings

What the fixes found that the audit did not say, or said differently. The
defect register (`docs/defects.md`, D218 onwards) has one row per item fixed.

- **N1.** The last-resort `catch` is around the frame loop's network-and-tick
  block, and it logs and goes on; it cannot name a peer to disconnect, because
  nothing that far out knows whose message was being handled. It is a floor,
  not the fix: every decode of a peer's bytes runs under `lua_pcall` on a
  thread of its own, so the message is dropped where it is read. The decode
  needed its own thread because two of the three callers decode onto a
  coroutine parked on a yield, where a protected call cannot run.
- **F2.** A backslash in a glTF URI is refused by fastgltf itself as an invalid
  URI, before the new check sees it; a GLB's own binary chunk arrives as a URI
  with an empty path and is the model's, not a file. The check is a first
  parse without the external files, then the real one -- the data buffer has
  to be rewound between the two.
- **F4.** `mesh_loader_tests.cpp` named its maps by absolute path: the hole the
  audit describes was what those tests relied on. They name them under a
  content root now.
- **S4.** The nesting limit is 100, not ~180: 100 runs clean on a 1 MiB Windows
  main-thread stack in a debug-info build, which is the smallest stack the
  engine runs scripts on.
- **S5.** `architecture.md` said a shipped game never kills a script; the owner
  decided on 2026-09-28 that an exported game stops one at 5 s (1 s wherever a
  person is testing), and the paragraph says so now.
- **S8.** The per-frame `LUA_GCSTEP` pacing the architecture describes is not
  part of this fix: the cap is the safety, and pacing is a performance change
  that needs the frame statistics the P1 performance work adds first. The
  allocator collects at once when a thread runs out, which is what keeps the VM
  usable after the cap is hit.
- **E3, the network half.** "Clamp an intent's magnitude to 1" would break an
  action bound to the mouse's motion, which reports pixels: each axis is made
  finite and held within ±1e6 instead, and the type within the enum. The
  intent names are looked up, and `Player:GetIntent` interns the name it is
  asked for -- the authority's own code is what makes a peer's intent for it
  arrive.
- **E1** found a defect of its own (D227): a replica rejoining its authority
  destroyed its `Workspace`, and every instance of the rejoined world had been
  parented under it.
- **The network review** (the owner's P0 note: `engine/net/`, `session.cpp`,
  `network_session.cpp` again) found eighteen more, in D230 to D232. Three of
  them the review had wrong or partly wrong:
  - the O(n²) in a snapshot was only a cost, never an error; ascending ids,
    which the authority already wrote, is what made a merge possible;
  - "clamp a count against remaining bytes" is not enough where each record
    costs a whole copy of a state (`forget`) or a scan of the message
    (`onAttributes`). Those were changed to batch and to a set, not bounded;
  - `network_session.cpp` holds no parsing of peer bytes of its own. Its
    failure modes are the session's, and nothing was changed there.

  **Left as it is:**
  - The `Player<N>` name atom made for each new player: one atom a
    connection, and connections are now bounded by address and by the hello
    deadline.
  - A replica keeps interning the authority's attribute names. They are the
    game's own, and the atom table is bounded (`MaxReplicaNames`).

  **Not reproduced by a test, and changed by reading alone:**
  - the aged, bounded held queue;
  - the identity bound, which needs 65536 connections;
  - ENet's limits, which the memory transport the tests run on does not
    have;
  - the index behind `instanceOfNet`, which shows as time and not behaviour.
- **S6** is right about the symptom and wrong about the mechanism. Luau 0.734
  gives atoms lazily -- when a string first names a member of a userdata, and
  when a chunk loads its field names -- so an ordinary string never reaches the
  callback, and "rebuilt strings" exhaust nothing. What does is a key built at
  run time, `workspace["x" .. i]`. The failure it causes is worse than the one
  described: every chunk loaded afterwards -- a module required later, a hot
  reload -- names no member at all, because its field names are given atoms as
  it loads.
- **S11** is fixed for the query paths only. The callback interned every key,
  and `RemoveTag` interned a tag it was only removing; neither does now. **Left
  for a decision:** an instance's `Name` and a `ProximityPrompt`'s
  `ActionText` and `ObjectText` are atoms by design. The snapshot wire has only
  fixed-size encodings, and text travels as an atom (the snapshot's name
  table). So `bullet.Name = "Bullet" .. n` still adds a name a bullet. Either
  change -- atoms counted and freed, or a string encoding on the wire (a
  protocol change) -- is an ADR's to decide, not a defect fix's.
